## 2. 開機層(每次上電;**開機不自啟**)

逐字指令在 `runbook.md` §A0,順序:**吊機先、本體後**。

```
ping .25/.26 ─► 吊機主程式(FIFO) ─► web ×2(吊機上, :8080/:8081) ─► 本體主程式(FIFO, 帶 FCV_EP_CRANE_HOST) ─► 手臂 motor_api(FIFO)
```

🔴 已知坑:`start_*.sh` 只在 Pi 的 `~/run/`、沒版控;`HOME_GROUND` 預設 256 是頂零舊慣例,**地歸零要傳 0**;
`FCV_EP_CRANE_HOST` 不帶不會報錯只會走錯路;WiFi/隧道現況見 `SOFTWARE.md` §1.3。

## 4. 清潔週期(`cycle_test.py full`,設計 p12/p13)

### 4.1 每步(下行 STEP_CM=40)

```
① fan OFF             pwm set 1 50 65535 5          ⚙本體 → QX-DO24
② vacuum feet on      單閥 VT307(4 吸盤共用)         ⚙本體 → PQW CH1
③ pusher all extend_raw                             ⚙本體 → ZDT 5-8 一段到 10 cm
③a 等真空             輪詢 status p5–p8,任一 ≤ −50 kPa,上限 10 s
                       吸不到 → 不中止、跳過 ③b、記數、續行
③b 清潔(有附著 且 不在橫桿跳過帶)
     滾筒 RIGHT wet:  arm_deploy_f 8 RIGHT → water_level 檢查 → water_pump on → brush on
                      → rail 100 → rail 0 → brush off → water_pump off → arm_retract
     刮刀 LEFT dry:   arm_deploy_f 8 LEFT → rail 100 → rail 0 → arm_retract
     deploy 回 OK/WARN 照掃;no_wall/obstacle → 先 arm_retract 再跳過
④ pusher all retract
⑤ fan ON(7%)
⑥ 等 1 s
⑦ pay_out 40          🐍 監看執行緒:tension_valid / roll / 左右差;roll 中止 → roll_recover + clear_error → 補完剩餘
⑧ 靜置 0.3 s 讀 raw_x(停後 roll)
```
**週期末 ⑨**:fan OFF → `set_motion_hz UP_HZ` → `retract (TOP−cur)` 回頂 → `set_motion_hz DOWN_HZ`。
**cleanup**(異常/結束):`arm_retract`、fan OFF、motion_hz 寫回;**吊機與推桿刻意不復位**(保留現場)。

### 4.2 設計 vs 實跑(逐條,都是上機後定案)

| 設計(PDF) | 實跑 | 類型 | 定案依據 |
|---|---|---|---|
| 螺旋槳貼牆 → 校平 → 吸附 | **吸附時關槳**,移動時才開 | 🔁 | 09-03:7–8% 推力下吸不上;關槳靠繩吸得到 |
| 四缸快伸 → 慢速逐缸接觸偵測 | `extend_raw` 一段到 10 cm | 🔁 | C++ 有 `smart_extend`/兩段式/`topup`,cycle_test **繞過** |
| 四路真空全達標;單顆不足微退 2 mm 重貼 ×3 | **任一顆 ≤ −50 kPa 即過;吸不到不重試、跳過清潔續行** | 🔁 | 09-03 per user:玻璃有縫是現場條件,不是故障;但必須看得見(逐步印+計數) |
| 行程差算玻璃傾角 → 手臂貼壓補償 | 無 | ⬜→不需要 | 手臂改**力控** `DEPLOY_F`(壓力是被控量,不用牆距) |
| 去程滾筒、回程刮刀(一趟) | 滾筒 0-100-0 wet,**再**刮刀 0-100-0 dry(**兩趟**) | 🔁 | 工具靠 M2 旋轉切換;09-11 定案每步雙組合 |

| 段高 = 滾筒寬 − 重疊 | 40 cm 測試參數 | 🔁 | 滾筒 510 mm ⇒ 設計值應 ~45–50,**未定案** |
| 陀螺儀 ≤ ±2°,否則差速推力修正 | — | ⛔ | 兩槳**同一路 PWM**,結構上無差動(HARDWARE §6) |
| 吊機微調水平 | 吊機 `hold_loop` IMU **連續**閉環;中止時 `roll_recover` | 🔁🐍 | 移動中平衡在 C++;**中止判定與復原在 Python** |
| 已到 1 樓?→ 下一段 | STEPS 固定;`BOTTOM` 常數擋 | 🔁 | 無「到底」判定 |
| 手臂歸位、刮刀抬起 | `arm_retract`(收 M1 離牆卸力,**不失能**) | ✅ | 09-11 per user:上電就使能,失能會亂跑 |
| 進水閥 → 水泵 → 刷(本體) | 進水閥在**吊機** ZS-DIO CH4(deadman 300 s);本體只管噴水 CH4 + 刷 CH5 | 🔁 | 06-05 搬到吊機 |

### 4.3 硬性守則(都是踩過才定,GUI/腳本都要遵守)

- **M1 下才開水;滑台回 0 才收手臂;收手臂前先關水;收手臂不失能**
- **風扇必須在推桿收回後才開;掃動時風扇關**(推桿仍在 10 cm 機體有支撐)
- **吸不到不中止,但必須看得見**(逐步印、計數、總結再報)
- **破真空順序不可變**:關真空 → 等 → 收推桿(v1 規格仍正確;真空未洩硬收會拉壞推桿)
- 力控 target **由呼叫端顯式傳值**(cycle_test `ARM_TARGET_NM`),手臂 default 只是備援
- 中止原因分兩類:**roll 造成的自動修正續行**;`tension_valid=0` / 左右差持續擴大 **不自動修正**(那是保護失效或發散)

## 5. 安全監看(設計 p14 vs 現況)

設計:**主動迴路**每 10 ms —— 通訊中斷 / 張力異常 / 姿態 > ±5° / 環境 → **進安全模式**(吊機停鎖、維持吸盤、
停手臂關水、槳降保壓)→ **通報**(聲光、故障碼)→ 人工回收。

現況:**沒有統一的安全模式,會動手的散在四處;GUI Dashboard 只顯示不動手。**

| 監看項 | 設計 | 現況會動手的在哪 | 狀態 |
|---|---|---|---|
| 張力(過載/差值/上限/收繩停) | 安全模式 | ⚙ 吊機 `hold_loop` → `hold_all_off` | ✅ 唯一完整的一項 |
| 通訊中斷 | 安全模式 | ⚙ 吊機 watchdog(motion 逾時);**本體端監看吊機是死碼**(待辦 🔴🔴) | ⬜ 半套 |
| 姿態 > ±5° | 安全模式 | 🐍 **cycle_test 監看執行緒**(不跑腳本就沒有) | 🐍 |
| 環境(強風、漏水) | 安全模式 | 無感測器 | ⬜ |
| 進安全模式(吊機停鎖 + 維持吸盤 + 停手臂關水 + 槳降保壓) | 一個狀態 | 各程式各自 abort;**沒有「維持吸盤」這種跨程式協調** | ⬜ |
| 通報 | 聲光 + 故障碼 | GUI `estop-banner` / log 而已 | ⬜ |
| 急停 | — | 本體 `emergency_stop` + 吊機 `stop`;⚠️ **實體急停有無、切不切 57.6V 未知**(HARDWARE §3.2C #12) | ⬜ |

**與 v2 Dashboard 的關係**:Dashboard = 顯示(高度/左右差/姿態/吸盤/幫浦/水位/張力條 + 門檻百分比)
+ **前置檢查閘門**(守起跑)+ **危險操作 60 s 解鎖**(守人的手)+ 快捷急停。**它不是安全監看** ——
瀏覽器關了就沒了,安全迴路必須在 C++。設計 p14 的「安全模式」是**跨兩箱的協調狀態**,目前不存在。
