## 2. 為什麼不照抄 `architecture.md`：「軸」這個抽象在這台機器上不成立

參考架構的 `IAxis`（`move_abs(pos, speed)` / `read_state()`）假設 **一個裝置 = 一個軸**。
實際盤點 14 支 driver：

| 類別 | 裝置 | 數量 |
|---|---|---|
| **真正的位置軸** | ZDT（吸盤推桿）、DM2J（上滑台） | **2** |
| **VFD：只有速度輸出、無位置回授** | SE3 ×2、MH300、CLV900 | 4 |
| **感測器（不是軸）** | SD76 計米 ×3、DSZL 張力 ×2、JC100 真空 ×4、DY500 重量 ×2、XKC 水位、WT901 IMU | 13 |
| **開關型致動器（不是軸）** | PQW 繼電器 ×2、QX-DO24 PWM、ZS-DIO | 4 |

🔴 **吊機的一條繩 = 三個裝置、三條匯流排**：
SE3 變頻器（USR_A/B，速度輸出）＋ SD76 計米器（USR_M，位置回授）＋ DSZL-107（X518 獨佔，張力）。
而且**是刻意拆開的**（`Crane_control_PI/main.cpp` 開頭寫著理由：單一 bus 掛掉時語意單純）。

→ 強行套 `IAxis`，這個閉環會沒有家。它現在就住在 `Crane_control_PI/main.cpp` 裡，跟協定攪在一起。

## 3. 目標分層：4 → 6 層 ＋ 1 個橫切

```
介面層 GUI              web_backend（Node，已是獨立行程）
      ↓ 文字協定
🆕 指令層 Command       84 個 cmd_* 的家：解析、FAST/SLOW 路由、參數驗證
      ↓ 流程命令
任務層 Task             狀態機、步態編排、sequence
      ↓ 工程單位（cm / kg / 度）
🆕 機構層 Mechanism     虛擬軸：速度輸出 + 位置回授 + 力回授 → 組成一個軸
      ↓ 裝置命令
驅動層 Driver           協定、暫存器、位元組序          user_lib/
      ↓ bytes
傳輸層 Transport        ✅ 已完成（2026-08-27）          transport/

橫切：安全層 Safety     監看 + 否決，**不在呼叫路徑上**
```

### 3.1 🆕 機構層 Mechanism（新增，三個理由每一個都踩過）

1. **虛擬軸**：吊機繩 = SE3 + SD76 + DSZL 的組合。閉環在這層，不在 driver 也不在 task
2. **機構標定的家**：`7.731 cm/圈` 是**皮帶軸**的性質，不是驅動器的。
   放進 `device_profile` 的話，換一顆同型馬達就會把標定重置 ——
   而它錯了的症狀是每次掃動下 131 cm 指令、滑台只有 50 cm，**四個月沒有人被告知**
3. **行程守衛**：`travel <= 48 cm` 由標定推導，屬於機構不屬於協定

### 3.2 🆕 指令層 Command（新增）

`WASH_ROBOT.cpp` 裡 **84 個 `cmd_*` vs 13 個 `do_*`** —— 六比一，介面協定壓過流程邏輯。

存在的直接理由：2026-08-27 把吸盤編號 1-4 改成 5-8 之後，
`zdt_pusher` / `zdt_disable` / `zdt_enable` **變成不可能成功** ——
分派器收 1-4、應用層收 5-8，**兩個範圍沒有交集**。
範圍驗證與被驗證的常數分居兩處就會分岔；指令層明確化之後，這件事變成「同一層吃同一個常數」。

🔴 **FAST / SLOW 雙路徑必須保留**：`stop` / `estop` / `status` / `pause` 走同步路徑。
理由是修過的 bug —— 長時間運動指令佔住收包執行緒時 `stop` 送不進去 ＝ **GUI 死鎖**。
**急停排在一個 15 秒的 move 後面，等於沒有急停。**

### 3.3 安全層 Safety（橫切，刻意不在呼叫路徑上）

放在呼叫路徑上的閘門遲早會被繞過 —— 2026-08-28 就有實例：合併帶進的
`sendAndReceiveQuiet()` 繞過同期加的 `MSG_NOSIGNAL` 防線，**git 一句話都沒說**。

→ 安全層應該是**獨立監看執行緒 + 否決權**（像現在的 `hold_loop()`），不是穿透式閘門。

### 3.4 `cleaning_arm` 不拉進來

3,041 行、**不使用 `user_lib`**、自建 socket 層、走 CAN，透過 TCP `:9527` 對外。
它**已經是一個服務邊界**，而且是全專案最乾淨的隔離。
參考架構沒有「跨行程服務」這個概念，但它在這裡是既成事實且運作良好 ——
**明確寫成架構的一部分，不是待重構的債。**

## 5. 🔴 等價性怎麼證明：黃金軌跡（golden trace）

**這支程式對外的契約 ＝「匯流排上的位元組」＋「TCP 回的文字」。**
兩者都一樣，重構就是正確的 —— 定義上如此，不需要靠人判斷。

→ 同一份指令腳本，分別餵給 `main-final` 與重構版，**兩者對假從站送出的位元組序列必須逐位元相同**。

### 已經有的（90%）

| 元件 | 現況 |
|---|---|
| **bytes 層 trace** | `LOG_HEX` 已在 15 支 driver（ZDT 就有 35 處），格式統一 `[時間] [DBG] [DEV:ID] TX xx xx` |
| **假從站** | `Linux_test/fake_slaves/` 已進版控：RTU-over-TCP + MBAP 兩種，可故意送壞幀 |
| **指令入口可腳本化** | 兩支主程式本來就走 TCP 文字協定（`:5001` / `:5002`），指令用管線灌 |

### 缺口（階段 0 要補的）

1. **端點注入**：5 個寫死的 IP 常數 + 17 個 `init()` 呼叫點
2. **假匯流排**：現有假從站一次只服務一個 slave，要能一台服務整條 bus
3. **正規化 + diff**：時間戳、連線順序、非決定性欄位
4. 🔴 **負控制**：先證明工具會失敗

### 🔴 為什麼「負控制」不能省

2026-08-29 才踩過：`test_qx_do24` 的斷言寫反（`if (init(...)) FATAL`，而 `QX_DO24::init()`
是 `true`=成功），**一個斷言都沒跑到卻回報通過**，那支測試從寫出來到當天從沒真正跑起來過。

→ **工具上線前必須先故意改壞一個常數，確認 diff 會紅。** 沒有紅過的綠燈不算綠燈。

## 5.5 🆕 驗證有兩級，先用便宜的那級

2026-08-29 做階段 1 時發現的：**「trace diff = 0」不是最強的判準，也不是最便宜的。**

| 工具 | 證明什麼 | 成本 | 什麼時候用 |
|---|---|---|---|
| **`harness/prove_noop.sh`** | **整個編譯單元的預處理輸出逐位元相同** | 幾秒，不需要 g++、不需要跑任何東西 | 純刪死碼、純搬動、只改註解 |
| `harness/compare.sh` | 跑到的路徑上，位元組與回覆相同 | 要建置 + 執行 | 真的改變了結構（抽函式、換介面） |

🔴 **`prove_noop` 更強的地方**：`compare.sh` 只涵蓋指令腳本跑到的路徑
（覆蓋率是它最弱的一環）；`prove_noop` 涵蓋**每一行**。
🔴 **它做不到的地方**：只要語意真的變了它一定紅，所以抽函式那種改動用不上它。

**原則：能用 `prove_noop` 證的階段，就不要動 `compare.sh`。**

### 排序的理由

- **階段 −1 是地基**：本分支的 9 條行為改變**一條都沒有實機證據**（2026-08-29 只做到
  `cl /Zs` 語法層）。在未驗證的基礎上重構，日後出現差異時**分不出是重構搬壞的、
  還是那 9 條本來就有問題**。這正是放棄「分兩段上機」時付出的代價 —— 歸因能力沒了。
  🔴 **但機器時間未定 → 階段 0 先做，−1 排到機器空出來時補。**
- **階段 1 刻意選「刪死碼」打頭陣**：預處理器本來就丟掉了，所以它是**唯一一個
  trace 必須完全不變的動作** —— 它同時是**驗證工具自己的第一次真實檢驗**。
  刪死碼若跑出差異，那是工具壞了不是程式壞了。
- **原本把吊機排第一是為了避開另一位工程師**。`main` 於 2026-08-29 凍結後
  這個理由消失，排序改由「什麼能解鎖驗證」決定。

## 7. 兩個已知陷阱（動手前先讀）

### 7.1 config 外部化會沖掉「理由」

那 228 個常數裡有些帶著**承重的沿革註解**：

- `CH6`（破真空）與 `CH14`（水泵）**絕不可同號** —— 同號＝清洗時開水泵等於開破真空閥，
  四顆吸盤同時失效、**機器在貼牆狀態下脫落**
- `CUP_PULSE_PER_CM = 3000` 的四條獨立證據
- `ARM_RAIL_LEAD_CM_PER_REV = 7.731` 的最小平方殘差

YAML 放不下 20 行理由。

→ **標定值**外部化並帶 provenance 欄位（來源／量測日期／方法／殘差）；
**互鎖規則**留在程式碼裡當斷言，**不要外部化成一個可以被人改錯的數字**。

### 7.2 「合併乾淨 ≠ 語意接得上」在重構時同樣成立

搬動程式碼時 git 只看文字。2026-08-28 的實例：對方新增的函式帶著 `send(..., 0)` 進來，
繞過我方同期加的 `MSG_NOSIGNAL`，兩邊沒碰到同幾行 —— **git 一句話都不會說**。

→ 每個階段結束時，除了 trace diff，還要問一句：
**「這次搬動有沒有讓某條防線變成繞得過去的？」**
