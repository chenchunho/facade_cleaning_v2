## 0. 🔴 最重要的發現：現在的實作是**反過來的**

`motion_fine_adjust_sync`（移動結束後的細調段）把兩側**對齊到繩長齊平**：
```
main was retract → target = min(L_cur, R_cur)   // 落後的一側繼續收到跟上
```
而 **IMU 平衡（`apply_balance_trim`）在移動中修出來的偏移，就在這一步被收掉。**

**證據（本日 retract 實測，繩長差與姿態同時記錄）：**

| | 起點 | 40cm | 40cm | 40cm | 26cm |
|---|---|---|---|---|---|
| 繩長差 L−R | **5** | 1 | **0** | **0** | **0** |
| `raw_x` | **+0.38°** | +5.20° | +5.66° | +5.83° | **+5.86°** |

⇒ 我剛用 `roll_correct` 修出的 5cm 偏移被逐步收成 0，姿態同步回到 +5.9°。

📌 **同一個機制解釋了本日所有現象**：每步 `停後roll` 都回到 +3~4°／`roll_correct` 修好撐不久／
`mission_run` 兩輪靜止傾角單調累積到 +3.72°。

🎯 **並且 `apply_balance_trim` 全程 `src=imu`**（`[BAL]` log 實證，trim 拉到 15Hz）——
**問題不是「沒用 IMU」，是 IMU 的成果在移動結束時被計米器細調覆蓋掉。**

## Phase 1 — 🎯 **主線**：把 `level_diff` 設成非零（不需要 IMU）

**不改任何程式碼**，只在開機後設定：
```
set_fine_adjust_level_diff 4          # 本日中位值
```
**預期效果**：移動結束的細調不再把繩長收到齊平，而是收到 L−R=4 ⇒ 姿態不再每次被推回 +3~4°。

### 🚦 驗收
跑一輪 `cycle_test 3 2 100`，看 **`停後roll` 是否由 +3~4° 降到 ±1~2°**，
以及 **Δmax 是否下降**（若姿態不再每步大偏，平衡迴路的 trim 需求變小 ⇒ Δ 應該跟著小）。

### ⚠️ 風險與限制
- 🔴 **不持久化**：重啟吊機就回 0，而**症狀是「安靜地退回舊行為」**。
  ⇒ 必須進啟動檢查清單，或與 `motion_hz`／`balance_source` 一起做持久化（既有待辦）。
- 🔴 **4 是本日中位值，不是量出來的常數**。若水平點隨高度變，單一常數只能對一部分高度成立。
- ⚠️ 這是**開迴路補償**：它假設偏移量已知且固定。真正的閉迴路是 Phase 3。

## Phase 2 — 你要的兩段式（誤差大用大 Hz、誤差小用小 Hz）

現有零件與缺口：

| 段 | 現有零件 | 現況 | 缺什麼 |
|---|---|---|---|
| **粗調（計米器）** | `roll_correct <cm>` + `g_roll_correct_hz`（5–50Hz 可設） | Hz **固定 10** | **依 \|roll\| 選 Hz** |
| 粗調收尾 | `g_roll_finish_hz` | **預設也是 10 ⇒ 收尾段等於停用** | 讓它真的低於 correct_hz |
| **細調（IMU）** | `apply_balance_trim`（連續頻率微調） | **只在移動中跑** | 靜止時的等價機制 |

### 2.1 粗調：增益排程（小改）
依 `|roll|` 決定 `roll_correct_hz`：例如 `|roll| > 4°` → 30Hz；`2~4°` → 15Hz；`< 2°` → 10Hz。
並讓 `roll_finish_hz` 固定為該值的一半（下限 5Hz），使既有的收尾減速段真正生效。

### 2.2 🔴 細調：靜止時的量化下限，這是真正的難點
`roll_correct` 的下限**不是速度問題，是量化問題**（`main.cpp` 註解 09-01 已寫明）：
> 指令是整數 cm、計米器讀數也是整數 cm，而 `roll_correct` **兩側各走 |delta|**
> → 最小差動 = 2cm → 最小步階 **2~4°**，而規格帶寬只有 2°（±1°）。
> **降速只能消除過衝，消除不了 1cm 的量化下限。**

**本日親自撞到**：`+3.27° →(+1cm)→ +1.06° →(+1cm)→ −2.96°`，一步跨過整個帶寬。

🔴 **而「讓 `apply_balance_trim` 靜止時也跑」不可行**：
```cpp
err = -direction × roll        // direction: retract=-1 / pay_out=+1
```
靜止時 `direction = 0` ⇒ **`err` 恆為 0**，公式在數學上產生不出修正量。
更根本地，它調的是**兩顆馬達的頻率差**，而靜止時兩顆都停著、沒有基準頻率可調。

✅ **正確方向：用時間控制而非距離控制的差動微動。**
兩側以低 Hz 跑一小段**時間**（例如左 8Hz、右 6Hz × 300ms），差動量 = Hz 差 × 時間
⇒ **不受計米器整數 cm 的量化限制**。這正是「誤差小就用小 Hz」的實作形式。
🔴 **本樹目前沒有這種機構**（`kick_hz`/`freeze_hz` 都只是頻率設定，不是「跑多久」）
⇒ **這是要新增的東西，不是把現有零件接起來。**

⚠️ **新增「機器在應該靜止時會動繩」的行為，是本計畫最需要你確認的一點。**

## Phase 3 — IMU 閉迴路（🔻 **per user 已降級為加分項，不是目標**）

⚠️ 原本我把這一段寫成「真正的閉迴路」＝終極方向。**per user 的判斷推翻了這個排序**：
走 192.168.1 之後 IMU 是唯一會斷的訊號，把主線建在它上面是把系統的可用性綁在最脆弱的一環。
⇒ **保留為加分項**：IMU 新鮮時可以修得更好，不新鮮時系統仍應由 Phase 1 撐住。

原內容（僅列方向）：

Phase 1 的 `level_diff` 是**開迴路常數**。若水平點隨高度／載重變，正解是
**讓細調段的收斂目標由 IMU 決定，而不是由一個常數決定** ——
即 `motion_fine_adjust_sync` 結束條件改看 `|roll|` 而非 `|L-R-level_diff|`。
這需要 2.2 的時間式微動先存在（否則量化下限會讓它收不進去）。
