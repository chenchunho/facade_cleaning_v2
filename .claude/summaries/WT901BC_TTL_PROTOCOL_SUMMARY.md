**🎯 實機佐證（09-07 實測）**：`n_accel(0x51)=42667`、`n_angle(0x53)=42894` 兩個計數同步累加；
`az=1.00 g`（重力全落在 Z 軸）⇒ **模組水平安裝，與手冊 `DIRECTION=0` 的座標定義相符**。

⇒ **WT901BC 與 WT901C 在 TTL 介面上是同一套協定**，這份摘要可用。

**🔴 五個落差（比對才發現的，不是 bug 但值得知道）**

1. **`0x54` 磁場封包完全沒有解析。** 而 RSW 出廠預設 `0b00011110` **包含 0x54**
   ⇒ 那些封包每次都通過 checksum，然後在 `switch` 裡**默默落地**。
   約 1/4 的串列頻寬在空轉；日後要用磁場時，要知道它其實一直在送。

2. **溫度從來沒被讀。** `0x51`/`0x52`/`0x54` 的 `buf[8..9]` 是溫度（`T = v/100 ℃`），driver 完全忽略。
   IMU 有溫漂，而這是**免費附送**的診斷訊號 —— roll 讀值可疑時，溫度是第一個該看的東西。

3. 🔴🔴 **`0x56` 氣壓封包那整條路徑無法驗證，而且極可能從未執行過。**
   - WT901C-TTL 的 datasheet **完全沒有 `0x56` 的格式定義**（該編號只在 RSW 位元遮罩裡出現過名字）
   - RSW **出廠預設不輸出 `0x56`**（預設只含 `0x51`~`0x54`）
   - 實查：`pressure` / `altitude` **應用層沒有任何一處讀取** ⇒ 死碼
   - 而 `.h` 的使用範例還印 `imu.altitude` —— **照著抄會得到一個恆為 0 的值**
   📌 這是「有 markup 沒人寫」的 C++ 版本，與 2026-09-07 在 console v2 抓到的是同一族。

4. ✅ **`0x53` 的末兩 byte 是「版本號」不是溫度** —— driver 正確地沒有去碰它。
   **這點值得記下來**：另外三個封包同位置是溫度，很容易寫成一體適用。

5. 🟡 **同步只靠 checksum，沒有驗封包類型。** `0x55` 可能出現在資料位元組裡；
   失步後找下一個 `0x55` 可能對到假封包，靠 checksum 擋下（約 1/256 會漏網）。
   **加一行「`buf[1]` 是否落在 `0x50`~`0x5A`」幾乎免費**，可把誤同步再降兩個數量級。
⚠️ **但規格數字（量程、精度、尺寸）仍屬 WT901C**，要引用具體精度前請以實物銘牌／原廠為準。
🟡 **待補**：per user 之後若拿到 WT901BC 自己的手冊，請覆蓋本檔並移除本節的但書。

## 本專案的接法

`/dev/ttyUSB0` @ **115200**（`WASH_ROBOT.h` `IMU_PORT` / `IMU_BAUD`），USB→TTL，
背景執行緒連續讀取。**不是 Modbus**，是單向主動上報的自訂封包。

🔴 **出廠波特率是 9600，我們用 115200 ⇒ 這顆被改過（波特率碼 `0x06`）。**
任何一次「恢復預設」（`SAVE` 寫 1）都會把它打回 9600，於是 IMU 安靜地停止上報，
而 roll 平衡會退回計米器路徑（吊機端 `imu_roll_fresh()` 會轉 false）——
**症狀是機器變歪，不是任何一支程式報錯。**

## 輸出封包格式

**固定 11 bytes**：`0x55 | <類型> | 8 個資料位元組 | SUM`
資料一律**低位在前、高位在後**，組成 **signed short**：

```c
Data = (short)(DataH << 8 | DataL);   // DataH 必須先轉成 signed short 再位移
```

| 類型 | 內容 | 換算 |
|---|---|---|
| `0x50` | 時間 | `YY MM DD hh mm ss msL msH`；`ms = (msH<<8)|msL` |
| `0x51` | **加速度** | `a = v/32768*16g`（g = 9.8 m/s²）；末兩 byte 是溫度 `T = v/100 ℃` |
| `0x52` | **角速度** | `w = v/32768*2000 (°/s)`；末兩 byte 溫度 |
| `0x53` | **角度** | `Roll(X)/Pitch(Y)/Yaw(Z) = v/32768*180 (°)`；末兩 byte 是**版本號**不是溫度 |
| `0x54` | 磁場 | `H = v`（原始值，無換算）；末兩 byte 溫度 |
| `0x59` | 四元數 | `Q = v/32768` |

**校驗**：`SUM = 前 10 個 byte 相加取低 8 位`。

### 🐛 手冊自己的兩個筆誤（別照抄）

- `0x50`（時間）那節寫 `Sum=0x55+**0x51**+YY+...` —— 應為 `0x50`
- `0x54`（磁場）那節寫 `Sum=0x55+**0x53**+HxH+...` —— 應為 `0x54`

✅ **實際規則就是「把前面 10 個 byte 加起來」**，不必逐型別背公式。
driver 的 `validateChecksum()` 正是這樣寫的，所以沒被這兩個筆誤影響。

## 設定指令

**格式固定 5 bytes**：`0xFF 0xAA <暫存器位址> <DataL> <DataH>`

| 位址 | 符號 | 意義 |
|---|---|---|
| `0x00` | SAVE | `0` = 保存目前設定、**`1` = 恢復出廠** |
| `0x01` | CALSW | `0` = 離開校準、`1` = 陀螺儀+加速度校準、`2` = **磁場校準** |
| `0x02` | RSW | 回傳內容（位元遮罩，見下） |
| `0x03` | RATE | 回傳速率 |
| `0x04` | BAUD | 波特率 |
| `0x05`–`0x07` | A?OFFSET | X/Y/Z 加速度零偏 |
| `0x08`–`0x0A` | G?OFFSET | X/Y/Z 角速度零偏 |
| `0x0B`–`0x0D` | H?OFFSET | X/Y/Z 磁場零偏 |
| `0x23` | DIRECTION | **安裝方向**：`0` = 水平、`1` = 垂直 |

🔴 **設定完必須寫 SAVE，而且要重新上電才生效**（手冊 §6.2.9 明載）。

**回傳內容 RSW**（`0xFF 0xAA 0x02 RSWL RSWH`）：RSWL 的 bit0–7 依序對應
`0x50 0x51 0x52 0x53 0x54 0x55 0x56 0x57` 封包，**出廠 `0b00011110`**
= 只輸出 `0x51 加速度`、`0x52 角速度`、`0x53 角度`、`0x54 磁場`（不輸出時間）。
RSWH 的 bit0–2 對應 `0x58 / 0x59 / 0x5A`。
📌 **本專案只需要 `0x53`（角度）**；若要降低串列埠負載可以只留它，但目前沒必要。

**回傳速率 RATE**：`0x01`=0.2Hz、`0x03`=1Hz、`0x06`=**10Hz（出廠）**、`0x08`=50Hz、
`0x09`=100Hz、`0x0b`=200Hz、`0x0c`=單次、`0x0d`=不輸出。

**波特率 BAUD**：`0x01`=4800、**`0x02`=9600（出廠）**、`0x03`=19200、`0x04`=38400、
`0x05`=57600、**`0x06`=115200（本專案）**、`0x07`=230400、`0x08`=460800、`0x09`=921600。

## 量程與精度（WT901C 規格，見上方但書）

| 感測器 | 量程 | 精度 |
|---|---|---|
| 加速度 | ±16 g | 0.01 g，16 bit，穩定度 0.005 g |
| 角速度 | ±2000 °/s | 16 bit，穩定度 0.05 °/s |
| 磁場 | ±4900 µT | 0.15 µT/LSB |
| **角度** | **X、Z 軸 ±180°；Y 軸 ±90°** | **X/Y 軸 0.05°；Z 軸 1°（且需先做磁場校準）** |

工作電壓 TTL 3.3–5 V、電流 < 40 mA、輸出頻率 0.2–200 Hz。

## 🔴 三個會影響本專案判讀的座標系事實

1. **座標系是「東北天」**：模組正放時，**前方 = X 軸、左方 = Y 軸、上方 = Z 軸**。
   歐拉角旋轉順序 **Z-Y-X**（先繞 Z、再繞 Y、最後繞 X）。
   ⇒ 本專案用的 `roll` 是 **X 軸**，量程 ±180°、精度 0.05° —— **是三個軸裡最可信的那個**。

2. 🔴 **Y 軸（Pitch）實際只有 ±90°，90° 是奇異點**。超過 90° 時 Y 會往回掉、而 X 會跳過 180°。
   ⇒ console v2 的 Dashboard **只畫 roll 不畫 pitch 是對的決定**（09-04 per user 由 3D 改回 2D 的理由
   是「只有 roll 是被規範與被控的」，這裡多一條技術上的支持）。

3. 🔴 **三軸是耦合的**：只有小角度時才會呈現獨立變化，大角度時會互相帶動。
   本專案工作範圍 ±3°，遠在小角度區 ⇒ 不受此限，但**不要拿這支感測器去判讀大角度姿態**。

4. **Z 軸（Yaw）精度只有 1°，而且要磁場校準過**。本專案不使用 yaw ✅ ——
   若日後要用，得先做 `CALSW=2` 磁場校準，而機體上有馬達與繼電器，磁環境不理想。

## 校準

- **加速度/陀螺儀零偏校準**：`0xFF 0xAA 0x01 0x01 0x00` → 靜置 → `0xFF 0xAA 0x01 0x00 0x00` 退出 → SAVE
- **磁場校準**：`CALSW = 2`，需繞三軸緩慢轉動整顆模組
- **手動零偏**：`0x05`–`0x0D` 直接寫偏置值；輸出 = 量測值 − 偏置值
- ⚠️ **安裝方向 `0x23`**：水平安裝與垂直安裝的解算不同。本專案模組是**平貼機體**，
  若有人把它改成 `1`，roll 的意義會整個改變 —— 而畫面上只會看到「數字怪怪的」。
