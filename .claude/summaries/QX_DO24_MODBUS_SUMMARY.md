## Overview

4-channel independent PWM output module, 32-bit ARM + independent hardware watchdog.
Used in this project as **slave 9 on the `.22` bus**, channel 1 driving the fan.

- Supply: DC 9~24V (limit 7~30V), reverse-polarity protected
- Output: **NPN + 1kΩ pull-up**, amplitude = VCC or 5V (**DIP switch**, not software)
- Frequency: 1Hz~200kHz, four channels independent
- Duty: 0~100.0%, resolution 0.1%
- Drive current = amplitude / (1000 + load input impedance)

## Communication Settings

- RS485 Modbus-RTU slave, function codes **0x03 / 0x06 / 0x10** only
- **Factory default: 9600 8N1, address 1** ← ⚠️ this project runs it at **115200, address 9**
- Address register `0x20` (1~255), baud register `0x21`, format register `0x23`
- Broadcast address 0 can read/write when the address is unknown (single device only)

## Register Map

所有 `0x` 開頭為十六進位。組態位址 = `40001 + reg`。

| Reg | 含義 | 範圍 | 權限 | 備註 |
|---|---|---|---|---|
| `0x00`~`0x03` | 通道 1~4 占空比 | 0~1000（=0~100.0%） | 讀寫 | 單位 0.1% |
| `0x04`~`0x05` | 通道 1 頻率 | 1~200000 | 讀寫 | 32-bit，**ABCD** 位元組序 |
| `0x06`~`0x07` | 通道 2 頻率 | 同上 | 讀寫 | |
| `0x08`~`0x09` | 通道 3 頻率 | 同上 | 讀寫 | |
| `0x0A`~`0x0B` | 通道 4 頻率 | 同上 | 讀寫 | |
| `0x0C`~`0x0F` | 通道 1~4 控制 | 0~65535 | 讀寫 | 見下方取值表 |
| `0x10` | **保存輸出** | 非 0 值 | **只寫** | 🔴 見下方警告 |
| `0x1A` | 頻率小數位 | 0 / 1 / 2 | 讀寫 | 決定頻率範圍 |
| `0x1B` | 輸出電平極性 | 0 低 / 1 高 | 讀寫 | |
| `0x20` | 設備通信地址 | 1~255 | 讀寫 | 預設 1 |
| `0x21` | 波特率 | 0~8 | 讀寫 | 3=9600（預設）、**8=115200** |
| `0x22` | 固件版本 | — | 只讀 | 十進位，如 100 = V100 |
| `0x23` | 通訊格式 | 0~6 | 讀寫 | 0=8N1（預設）、1=8O1、2=8E1、3=8N2… |
| `0xFF00` | **特殊命令** | — | **只寫** | `0x01`=重啟設備、**`0xFFFF`=恢復出廠設置** |

### 韌體 V345 以上新增的第二組暫存器（2025-09 之後出貨）

`0x30`~`0x43`，作用與前面**完全相同且雙向同步**，差別只有兩點：
**位元組序是 CDAB**（不是 ABCD），且控制暫存器是 32-bit（脈衝數可超過 65535）。
用途：主機習慣 CDAB、或單次脈衝數 > 65535 時。**任選一組操作即可。**

### 控制暫存器取值表（`0x0C`~`0x0F`）

| 值 | 功能 |
|---|---|
| `0` | 關閉（無輸出，等同占空比 0%，輸出低電平） |
| `65535` (`0xFFFF`) | **持續輸出模式** —— 適合舵機／**PWM 風扇**／無刷電機等要求一直有信號的設備 |
| `1`~`65534` | 脈衝模式：寫＝要輸出的脈衝個數；讀＝剩餘個數 |

## 🔴 寫入壽命：哪些暫存器會磨損 flash

手冊明文（P3 注 3、P6 第 7 條）：

- **`0x00`~`0x0F`（占空比／頻率／控制）與 `0x30`~`0x43` 是「臨時生效、斷電恢復」**
  → **不消耗保存次數，可無限修改**
- **其餘暫存器（含 `0x20` 地址、`0x21` 波特率、`0x23` 格式）是「實時保存、斷電記憶」**
  → **請勿頻繁寫入**
- `0x10`【保存輸出】把 `0x00`~`0x0F` 現值存成開機預設。
  🔴 **內部儲存器擦寫壽命僅約 1~2 千次**，廠商因客戶頻繁保存燒毀而加了限制：
  **每次上電只能對 `0x10` 寫一次**。頻繁保存導致的損壞不予保修。

⇒ 本專案的 `pwm set` 只寫 `0x00`/`0x04~0x05`/`0x0C`，**全部落在無限次修改的區間**，不磨 flash。
`saveOutputAsDefault()`（寫 `0x10`）才會消耗次數，一次上電只能用一次。

## 🔴🔴 頻率寫入：FC 0x10 不是唯一選擇（2026-09-02 現場關鍵）

手冊 P4 第 2 條：

> b. 可以使用 **0x10** 功能碼，支持同時寫入多個寄存器
> c. 如果使用 **0x06** 功能碼單獨寫入，注意不能超過範圍，否則返回錯誤
> **若頻率低於 65535，則保持 `0x04` 的值為 0，只改 `0x05` 的值即可**

⇒ **頻率 ≤ 65535Hz 時，可以只用 FC `0x06` 單寫 `0x05`（請求 8 bytes），
不必用 FC `0x10` 寫兩個暫存器（請求 13 bytes）。**

📌 **為什麼這件事重要**：本專案的頻率鎖定在 **50Hz**，遠低於 65535。
而 `QX_DO24::setPWM_Freq()` 目前**只實作了 FC `0x10`** 那條路徑
（`setPWM_Duty` 與 `setPWM_Control` 用的都是 FC `0x06`）。
2026-09-02 現場 `pwm set` 全數失敗於 `pwm_freq_write_failed`，
而 `setChannel()` 在第一步就 `return false` ⇒ **後面兩個 8-byte 寫入根本沒被測到**。
若當時的故障確實是「長幀進不去」，改用 FC `0x06` 單寫 `0x05` 就能繞過。

## 端子定義（P9）

```
VCC  直流電源正        GND  直流電源負
A    RS485 通信 A 端    B    RS485 通信 B 端
撥動開關  選擇 PWM 輸出電壓幅值（VCC 檔 / 5V 檔）
DO1~DO4  各通道信號正端        GND  信號公共負端
```

🔴 **`VCC`/`GND` 與 `A`/`B` 在同一排、緊鄰。** 而保修除外條款（P14）第 2 條明列：

> **電源錯接到 485 接口以致 485 部分被燒壞**

⇒ 接線滑脫把電源碰到 A 或 B，會燒掉 RS485 段而模組其餘功能看似正常。
**症狀會是方向性的**：模組還發得出（讀取偶爾成功），但收不進（寫入全滅）。

## 應用注意（P11~P13）

- **PWM 風扇／無刷電機**：常見要求 PWM 頻率 **約 18kHz**（本專案鎖 50Hz，依實際設備而定）；
  需對控制暫存器寫 `65535` 開啟持續輸出
- **脈衝模式頻率上限**：單路 50kHz，四路同時 10kHz；超過會有脈衝個數偏差
  （持續輸出模式無此限制，全頻率範圍可用）
- **步進驅動器**建議共陰接法；共陽接法電平反向（實際占空比 = 100 − 設定值），
  可用極性暫存器 `0x1B` 反轉
- 幅值選擇是**硬體撥碼開關**，不是暫存器

## 與本專案驅動的對照（`user_lib/QX_DO24.cpp`）

| 驅動方法 | 功能碼 | 暫存器 | 請求長度 |
|---|---|---|---|
| `setPWM_Duty` | `0x06` | `0x00`+ch | 8 bytes |
| `setPWM_Freq` | **`0x10`** | `0x04`+ch×2 | **13 bytes** |
| `setPWM_Control` | `0x06` | `0x0C`+ch | 8 bytes |
| `saveOutputAsDefault` | `0x06` | `0x10` | 8 bytes |

- 驅動額外加了**安全鎖**（手冊沒有）：占空比 5~10%、頻率鎖 50Hz。
  理由是本專案的占空比視窗（5%=停 / 10%=全速）只在 50Hz 下成立
- 🔴 **驅動未實作 `0xFF00` 重啟命令**（`0x01`）。它是 FC `0x06` 的 8-byte 短幀，
  在「長幀不通」的故障下**可能是唯一還送得進去的命令**，值得加
- 🔴🔴 **絕不可誤寫 `0xFF00` = `0xFFFF`** —— 恢復出廠設置會把地址打回 1、波特率打回 9600，
  模組直接從 `.22` 匯流排上消失（本專案是 115200 / slave 9）
