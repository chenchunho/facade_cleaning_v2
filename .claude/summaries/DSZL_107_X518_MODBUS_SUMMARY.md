## 🔴 最重要的一件事：`DSZL_107` 這個 driver 名稱是誤導的

**DSZL-107 本身不是 Modbus 裝置**，它是一顆**類比應變片測力元件**：
輸出 2.0 mV/V、阻抗 350 Ω、供電 5–15 V。它沒有任何數位介面。

真正在講 Modbus 的是 **X518 雙通道採集器** —— 它把兩顆 DSZL-107 的 mV 訊號數位化。
⇒ `user_lib/DSZL_107.{h,cpp}` 從第一個位元組到最後一個，講的都是 **X518 的協議**。
📌 讀那支 driver 時要拿本檔的「X518」段對照，拿 DSZL-107 規格書對照會什麼都對不上。

### DSZL-107 規格（只有這些會影響判讀）

| 項目 | 值 |
|---|---|
| 額定量程 | 20–300 N（型錄另列 kg 版：2/5/10/20/30/50/100 kg） |
| 輸出靈敏度 | **2.0 ± 0.1% mV/V** ← 與 X518「靈敏度」參數預設 2.0000 相符 |
| 非線性／滯後／重複性 | 各 0.1% F.S. |
| 蠕變（30 分鐘） | 0.1% F.S. |
| 零點溫漂／靈敏度溫漂 | 各 0.05% F.S./10℃ |
| **安全過載 / 極限過載** | **150% / 200% R.C.** |
| 響應頻率 | 1 kHz |
| 工作溫度 | −20 ~ 80℃ |

⚠️ **本專案用的是哪個量程版本，手冊查不到**（那是型號選配）。
這件事有實際後果：`TENSION_MAX_KG_DEFAULT = 100`（單側）目前被記為「整機才 94 kg，
一條繩承擔全部重量也不會觸發」——**若元件本身就是 100 kg 版，那 100 kg 同時也接近它的額定值**，
兩件事會撞在一起。要查請看元件銘牌。

## X518 採集器

### 出廠預設（**與本專案實際使用一致，2026-09-07 對照確認**）

| 項目 | 出廠值 | 備註 |
|---|---|---|
| IP | `192.168.1.120` | 參數 `IPH=192168`（0x63e）／`IPL=1120`（0x640） |
| Port | `502` | 0x642 |
| 以太網協議 | **1 = Modbus-TCP** | 0x644（2 = ASC_TCP 主動上傳） |
| 機碼（slave） | `1` | 0x63c / 0x64c |
| RS485 | 115200 N81 | 0x636 / 0x638 |
| **單位** | **5 = N** | 0x614。1-t 2-**kg** 3-g 4-kN 5-N 6-lb |
| 小數點 | 2 | 0x616 |

### 🔴 只支援兩個功能碼

> 「採集器的 RS485 口支援 modbus-RTU 協議的 **03 讀指令**和 **10H 寫指令**，
> **所有讀寫資料均為 32 位**」

⇒ **沒有 FC 06 單暫存器寫**。每次寫入都是「2 個暫存器 = 1 個 32 位參數」。
⇒ 每個參數佔**兩個**連續位址（所以位址表是 0x600、0x602、0x604… 跳兩格）。

### 位元組序（會咬人）

預設 **高字在前**（d3d2d1d0）。可用參數 `0x638`「資料格式」把十位設為 1 改成**高字在後**。
⇒ 讀到的值若像是被拆成兩半的亂數，先懷疑這個參數，不要先懷疑感測器。

### 實時資料暫存器

| 位址 | 內容 |
|---|---|
| `0x0A00` | 通道 1 測量值（32 位有號，佔 2 個暫存器） |
| `0x0A02` | 通道 2 測量值 |
| `0x0A1E` | 標定砝碼（寫入標準負荷值） |
| **`0x0A20`** | **通信命令暫存器**（見下） |
| `0x0AC8` / `0x0ACA` | 峰值捕獲（需先設觸發門限） |
| `0x0ADC` / `0x0ADE` | 谷值捕獲 |

📌 本專案 `.h` 的註解「CH1 = 0x0A00、CH2 = 0x0A02，`get_both_long` 一次讀 4 個暫存器」
與手冊逐字相符 ✅。

### `0x0A20` 通信命令全表（driver 只用了其中四個）

| 寫入值 | 動作 | driver 有實作？ |
|---|---|---|
| `1` / `2` | 單一通道清零（CH1／CH2） | ✅ `do_zero_ch1/ch2` |
| `7` | **全部通道**清零 | ✅ `do_zero_all` |
| `11` / `12` | **實物標定**（加已知負荷後校準該通道） | ❌ |
| `21` / `22` | **數字校準**（用量程＋靈敏度算） | ❌ |
| `30` | 恢復出廠 | ❌（也不該實作） |
| **`40`** | **保存資料到儲存器** | ✅ `save_params` |
| `51` / `52` | 硬體零點校正 | ❌ |
| `61` / `62` | 硬體滿度校正 | ❌ |
| `101` / `102` | 通信觸發峰值捕獲及啟動記錄 | ❌ |

🔴 **手動恢復出廠還有實體途徑**：斷電下長按 K 鍵，保持長按再上電。
—— 現場維修時要知道這件事，它會把 IP 與波特率一起打回出廠值。

## 🔴 三個會靜默影響量測的預設值

### ① 上電自動清零（預設**開啟**）

> 「上電清零是在上電後 **2-3s** 後自動完成」，範圍受「上電清零範圍」（`0x600`，預設 50）限制。
> 受參數「清零模式」（`0x606`，**預設 11**）影響：個位為 0 時關閉。

⚠️ **對本專案的意義**：X518 上電當下若鋼索已經承重，那個重量會落在「零點」裡。
預設清零範圍只有 50（AD 值），所以正常吊重不會被吃掉——**但這是靠範圍限制擋的，不是靠邏輯**。
📌 **開機順序因此有意義**：先確認機器狀態再給 X518 上電，比反過來安全。

### ② 零位跟蹤（預設**開啟**）

> 「當系統穩定、測量值在『零位跟蹤範圍』（`0x604`，**預設 0**）時自動將測量值清零，**500ms 執行一次**」

✅ **預設 0 ＝ 實質關閉**，目前不影響。
🔴 **但如果有人把 `0x604` 改成非 0，緩慢變化的張力會被持續吃掉而完全沒有徵兆** ——
那正好是「繩索潛變／溫漂」這種本專案會遇到的訊號。**不要為了讓讀值好看而開它。**

### ③ 校準不保存就會遺失

> 「所有參數修改後（包括直接修改、清零、校準、恢復出廠等）都需要執行**資料保存指令**，
> 否則重新上電後資料會遺失」

⇒ 寫 `40` 到 `0x0A20`。**保存期間 CPU 停止所有操作，通信返回會有 100ms 以上延遲** ——
`save_params` 之後緊接著讀值可能逾時，那不是故障。（driver `.h:150` 的註解已記載此點 ✅）

## 📌 與本專案現行做法的落差（值得討論，非 bug）

**手冊提供了裝置端校準（`0x0A1E` 寫標準值 → `0x0A20` 寫 11/12），本專案沒有用它**，
而是在上位機乘一個軟體係數：

```cpp
static constexpr double DSZL_SCALE_RIGHT = -0.0236364;   // CH1，4.16kg → raw -176
static constexpr double DSZL_SCALE_LEFT  = -0.0205816;   // CH2，4.16kg → raw -202.1
```

兩種做法的差異：

| | 裝置端校準（`11`/`12`） | 現行的軟體係數 |
|---|---|---|
| 讀值單位 | 裝置直接吐工程單位 | 上位機自己換算 |
| 換一台上位機 | 跟著裝置走 | **要記得把係數帶過去** |
| 換一顆感測器 | 重新標定即可 | **要改程式並重新編譯** |
| 目前的 work_log 待辦 | — | 「單點校正（過原點），4.16 kg 外推到 30~60 kg 的線性度未驗」 |

🟡 **不是說現在做錯了**——軟體係數的好處是改參數不必碰裝置、也留在版控裡。
但**手冊裡有一條沒被用到的路**，而它剛好能回答那個「線性度未驗」的待辦：
裝置端校準可以在工作範圍內加標準負荷直接標定，不必從 4.16 kg 外推。

⚠️ 手冊自己也警告：數字校準（21/22）用的靈敏度**若是理論值而非實測值，校準結果不可信**。
DSZL-107 規格書上的 2.0 mV/V 帶著 ±0.1% 公差 —— **那是理論值**。
⇒ 要用裝置端校準，走**實物標定（11/12）**，不要走數字校準。

## 其他（本專案未使用，但列出免得下次重查）

- **主動上傳模式**：`0x634` 通訊協議設為 2 ＝ RS485 主動送 ASC（`asc+1111.1+2222.2\r`）。
  🔴 **一旦設成主動發送就不能再互動通信**，只能靠以太網改回來或恢復出廠。
- **D.AS_TCP 協議**：固定 20 byte 的 ASC 交互指令（`READ`/`WRIT`/`ZERO`/`RSTC`/`SAVE`…），
  另有非同步高速上傳（每包 100 筆、約 15 ms）。本專案走 Modbus-TCP，用不到。
- **採集速度** `0x61a`：0-8 對應 6.25 ~ 3200 次/s，**預設 80**（超出 0-8 範圍，手冊此處存疑）。
- **濾波**：`0x60c` 數字濾波深度（預設 8，千位為 1 開啟穩定濾波）／`0x60a` 振動濾波 0-3（FIR，預設 0）。
  ⚠️ 手冊提醒「對於快速測量，穩定濾波可能會影響測量結果」。
