FCV 通用閘道板

Pi 5 直接插在板上，左進下出。一片 PCB、兩種上件，取代六台 USR 網關、兩顆 PQW 繼電器模組與一顆 QX-DO24 PWM 模組。24V 單一輸入。

日期 2026-09-09 v0.6 PQW 8 路經 per user 確認 · 模組會替不存在的通道編造回覆 狀態 討論中，未定案

板面配置

圖 1 · 左進下出

電源與網路從左邊進，所有現場輸出從下緣出。Pi 5 上板之後這片板子同時是 Pi 的電源、Pi 的網路、以及全部現場匯流排的前端 —— 匯流排時序（DE/RE 翻轉、t3.5 幀間隔、CRC）都收在 STM32 裡，Pi 拿到的永遠是完整的幀。

選 push-in，不要螺絲

這台機器身上有 VFD、螺旋槳與吊繩運動，振動是常態不是例外。螺絲端子會鬆，而鬆掉的徵兆通常是間歇性通訊失敗 —— 那正是這個專案已經花很多時間在追的症狀（.22 那條匯流排至今沒定案）。鳳凰的 push-in 彈簧籠系列抗振，也不需要定期複緊。

六台網關跑的是純透明傳輸（mdm=0）加自動打包（_pt=0）。115200 下字元間隔只有約 0.3 ms，封包邊界完全交給網關猜 —— 一個 Modbus 回覆常被切成多個 TCP 段送出，而十二支驅動裡只有 QX_DO24 會累積分片。

ESC 訊號：這一路不是風扇

v0.3 · 最需要注意的一段

文件裡到處寫「PWM 風扇」，但程式碼寫的是螺旋槳。它在收腳與吊機移動期間開到 7%、伸腳之前必寫 5%（停止）—— 也就是說，它是在四顆吸盤沒有全部抓住的那段時間提供貼牆推力的東西。把它當散熱風扇設計會做錯失效狀態。

常數值意義
PWM_STEP_CH1只用一路 —— 與「2CH，其中一個備用」吻合
PWM_STEP_MOVE_DUTY_PCT7.0 %收腳 + 吊機移動期間
PWM_STEP_OFF_DUTY_PCT5.0 %停止。伸腳之前必寫
driver 占空比鎖5 ~ 10 %5% = 停止、10% = 全速
driver 頻率鎖50 Hz週期 20 ms
那個「安全鎖」其實是協定，不是保守值 50 Hz 下 5% = 1.0 ms、10% = 2.0 ms —— 這就是標準的 RC 電子變速器脈寬協定。驅動的標頭自己寫得很清楚：「占空比的 5%=停止 / 10%=全速 只有在 50Hz 才成立；換成模組的上電預設 1000Hz，同樣的 10% 只有 0.1ms，調速器收到的是無效訊號。」⇒ 板子要輸出的是脈寬，不是占空比；占空比只是它在 50 Hz 下的表達方式。
板子在這裡可以做得比模組好 QX-DO24 的占空比是 0.1% 一階，50 Hz 下 = 20 µs，而 ESC 的可用範圍只有 1000 µs 寬 ⇒ 整個油門只有 50 階。STM32 的計時器用 1 MHz 就能做到 1 µs 一階，1000 階。建議：暫存器圖照抄 QX-DO24 以維持零改動，另外開一個「直接寫脈寬（µs）」的擴充暫存器，日後想要細解析度時驅動再接上去。
🔴 失效狀態是「保持」，不是「停止」 app/WASH_ROBOT.h:578 記著現況：「寫入失敗時模組保持前一個輸出，通訊斷掉螺旋槳不會停；左右螺旋槳共用 CH1」。這是對的行為 —— 螺旋槳在收腳期間停掉，等於在最不能失去推力的時候失去推力。
⇒ 所以 ESC 這一路與繼電器相反：Pi 失聯時必須繼續輸出最後一個脈寬，不可以掉到 5%，更不可以停止送脈衝。
🔴 合併帶來的代價：失效隔離變差 今天 QX-DO24 是獨立模組、有自己的 MCU，所以 Pi 當掉、網路斷掉、甚至整條匯流排掛掉，螺旋槳都還在轉。把 PWM 搬到共用的 STM32 上之後，STM32 一當機就連螺旋槳一起帶走 —— 這是合併換來的隱性損失，值得在拍板前看見。
緩解：把 ESC 的脈衝交給硬體計時器自主輸出，不依賴 Modbus/乙太堆疊是否還活著（堆疊卡住時計時器照跑）；配獨立看門狗；並確認 ESC 自己對訊號中斷的行為是保持還是停止。剩下的殘留風險是 STM32 的完整重置，那會讓 GPIO 回到 hi-Z。
  • 冷開機時不要送脈衝。ESC 需要看到最小油門一段時間才會 arm；開機當下機器不在步伐中，沒有脈衝是安全的。韌體就緒後再明確送 1.0 ms 並保持 arming 時間，之後才接受油門指令。
  • 訊號電位：多數 ESC 吃 5V 邏輯，3.3V 通常也觸發得動。建議推挽輸出並保留 5V 選項，訊號地與 ESC 共地。

Pi 5 上板帶來的兩件事

網路與電源

一、Pi 的網路要靠板上的交換晶片

Pi 5 的乙太網路只從它自己的 RJ45 出來，40-pin 排針上沒有。而 Pi 同時需要兩條路：跟 STM32 講 TCP，以及對外走拖纜到另一台機器與 GUI。所以板上必須有一顆三埠交換晶片。

交換晶片埠接到實體
P1STM32RMII 直連（MAC 模式）—— 不需要另一顆 PHY
P2Pi 5磁環 + 板上 RJ45 → 一條短跳線接到 Pi 的 RJ45
P3對外上行 RJ45（左緣）：拖纜 / GUI / 另一台機器 / X518
順帶的好處 每片板自帶交換之後，外部那台 8-port PoE switch 的工作大部分被吸收：原本要接兩台 Pi 加六台網關，現在只剩拖纜、X518 與兩片板。
唯一不優雅的地方，以及替代方案 那條 Pi ↔ 板子的短跳線，是「Pi 上板」與「走 TCP」兩個決定撞在一起的產物，繞不掉。要拿掉它只有一條路：STM32 改當 USB 乙太網路裝置（CDC-NCM） —— Pi 會看到一張網卡，TCP 照用、驅動照樣零改動，不需要交換晶片也不需要跳線，Pi 的 RJ45 還空出來對外。代價是 STM32 韌體要多做一套 USB 網路堆疊。兩條都成立，看你要把複雜度放在硬體還是韌體。

  • 🔴 從 40-pin 排針餵 5V 會讓 Pi 5 認不出 5A 電源，預設把下游 USB 限到 600 mA。要嘛在 EEPROM 設定裡打開高電流模式，要嘛接受 —— 但 IMU 與手臂 CAN 都不走 Pi 的 USB 了，這限制可能無所謂。

PWM 上板 = 本體少一整段 RS485

連帶效果

QX-DO24 目前獨佔本體的 .21 整條匯流排。它被拉出來是因為 2026-09-03 六次多週期測試四次整條 .22 一起掛掉，拆開同時是一個分辨實驗。ESC 訊號收進板內之後，那個實驗與那條匯流排都不必存在了。

照抄暫存器圖 = 驅動零改動 韌體模擬 slave 9 的 QX-DO24 暫存器圖：0x00~0x03 四通道占空比（0~1000 = 0~100.0%）、0x04~0x0B 各通道頻率、0x0C~0x0F 控制暫存器，功能碼只有 0x03 / 0x06 / 0x10。user_lib/QX_DO24 一行都不用改，連驅動裡那個 5~10% / 50Hz 的鎖都在原處。實體只做 2 路：寫入不存在的通道回例外碼，讀取回「無輸出」——pwm status 會讀全部四路，讓它報錯反而像故障。
一個待拍板項會自動消失 QX-DO24 的 0x10【保存輸出】寫的是壽命僅 1~2 千次的 flash，而 console v2 的 pwm save 按鈕 09-08 因為共用 handler 一併失去了確認彈窗，目前掛在待辦上。原生 PWM 沒有這個限制 —— 板子換掉之後那條待辦不必再處理。

韌體要保證的三件事

價值都在這裡
01 / 幀

一次 write，一個完整幀

USART IDLE + DMA 做 t3.5 幀間隔判定，CRC 驗過才上送。Pi 端一次 recv 就拿到完整幀，那六支沒有分片防護的驅動不必回頭改。

02 / 越界

寫入越界要報錯，讀取回無輸出

寫不存在的通道回 0x02 Illegal Data Address；讀取則回「無輸出」不報錯（狀態查詢會掃全部通道）。寫錯是 bug，讀取是巡檢。

03 / 參數

線路參數由角色 profile 決定

SE3 那兩段的 8N2 變成韌體常數而不是網頁欄位。要調整就改韌體、進版控、留得下沿革。

02 要防的是這個 PQW 實體是 8 路（2026-09-09 per user 確認）。而程式裡有兩個常數超出範圍：CH_WATER_PUMP = 14（app/WASH_ROBOT.h:491）與 PQW_TOTAL_CH = 16（:443，2026-07-24 由 8 改 16，理由是「讓 readAllStatus() 涵蓋 CH15」—— 而 CH15 從來不存在）。
前例就在同一批改動裡：CH_BRUSH 被改成 15，之後每次 controlRelay 都打空，實機滾筒整段不轉、帳面全綠，五週後才發現。
🔴 而且模組不會拒絕越界：2026-09-09 實測 relay_status 對這顆 8 路模組回 ch1~ch16、沒有任何 Modbus 例外 ⇒ 它會替不存在的通道編造回覆。這正是保證 02 要擋的東西 —— 現行硬體在這件事上會說謊，板子不可以跟著說謊。

安全狀態不是一致的 OFF CH6 瞬跳導通 = 四顆吸盤同時失壓 = 機器在貼牆狀態下脫落。所以每一路的驅動輸入都要加下拉，讓 MCU 在開機、重置、韌體當掉時的 hi-Z 等於繼電器 OFF。但 CH1 與 CH2 相反 —— 它們維持吸附，設計成「失聯就全斷」反而會製造墜落。要逐路定義，不能寫一條全域規則。
📌 而 ESC 那一路又是第三種（失聯要保持輸出）—— 全板總共有三種失效語意，這件事本身要寫進韌體文件。
  • 回讀要讀接點實際狀態，不是讀回命令暫存器。現行 pqw_set_relay_verified_ 的三次重試是在對付匯流排 stale frame；改成板內回讀之後既沒有匯流排也沒有 stale frame，若同時接到實際輸出（輔助接點或電流偵測），那個 verified 才真的驗到物理 —— 而繼電器狀態燈就接在這個回讀上。
  • 端子絲印寫功能名，不要只寫通道號。CH6 與 CH14 之所以能撞，是因為「通道號」是唯一身分，而它同時活在程式常數與實體接線兩個地方。絲印寫 VALVE / PUMP-A / PUMP-B / INLET / BRUSH / BREAK-VAC / SPARE / SPRAY，接錯就看得見。
  • TTL 端子的方向要標。絲印寫 VCC · TX→ · ←RX · GND（板端視角）並註明 TX→IMU RX。VCC 做成 3V3/5V 可跳，WT901BC 兩者都吃，但接錯的代價不對稱。

選型與待補

畫板之前

MCU 需求：6 段 RS485 + 1 路 IMU UART + 1 路除錯 = 8 個序列埠，外加 CAN、乙太網路 MAC、2 路計時器 PWM、8 支繼電器 GPIO 與 23 顆狀態燈（可用移位暫存器省腳位）。STM32F429／F439 有 8 個 USART/UART 加 ETH MAC 與 2× CAN，剛好吃下但沒有餘裕；想留空間就往 F767 或 H743。若把除錯口改走 SWO 或 USB，就多出一路可用。

ESC 對訊號中斷的行為
脈衝停掉時這顆 ESC 是保持最後油門還是切到零？這決定 STM32 重置那個殘留風險有多大 —— 若 ESC 自己會保持，風險小很多；若會切零，就得認真考慮把 ESC 脈衝隔離到不受主 MCU 重置影響的地方。廠牌型號也還沒有記錄。
CH1 / CH2 失電極性
斷電是保住吸附還是失去吸附？決定繼電器段的 fail-safe 策略，而判斷錯的後果是墜落。文件裡沒有記載。
各負載電壓 / 電流
幫浦、刷馬達、電磁閥。決定機械繼電器或 SSR、接點額定、續流二極體、24V 輸入的保險絲與銅厚。規格書的電源分組自己標明是 v1 時期、已知過期。
RS485 線長與拓樸
六段都沒有記錄，也不知道是菊鏈還是星狀。決定端接電阻與失效安全偏壓的取值 —— 建議不論如何都做成可切換，等於不必先知道答案。
Pi 5 的機構與散熱
主動散熱器的高度、40-pin 之外要不要另拉電源連接器（5A 走兩支 5V pin 偏緊）、以及板子在機櫃裡的固定方式。左進下出的方向也要跟機櫃開孔對得上。
要不要預留安全互鎖
STM32 坐在每一條匯流排上，天生能做次毫秒的否決。現在不做可以，但要不要留這條路會決定 MCU 等級與韌體分層，事後補很貴。吊機側若要做張力互鎖，STM32 還得自己當一次 Modbus-TCP client 去讀 X518。
